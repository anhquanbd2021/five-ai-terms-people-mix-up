Pair-by-pair guide

Wrong model → failure → test

Every lab in this demo runs one of the five pairs from the article. This page maps each simulator to the mental-model mistake it demonstrates and the one-line test that catches it.

Simulations, not benchmarks. Models are deterministic fakes (seeded RNG), prices are illustrative constants, and the doc store is three paragraphs. The point is the shape of each failure, not the numbers' absolute size.

Start here

What this demo proves

Each pair is a fork in a build plan. Pick the wrong side and the failure is predictable: fine-tune for facts and every doc update is a retrain-or-stale decision; run a loop without a goal and the budget cap is the only stop; trust a bare prompt and a coin-flip output format fails in production; rely on context as memory and early facts scroll away; ship a prototype and the delivery gates block it. The labs make each fork visible with the wrong pick first.

The five pairs

Lab → wrong model → test

Pair 01

RAG vs. fine-tuning

Wrong model: "teach the model our docs" — a knowledge problem treated as a training problem.

Failure: the snapshot freezes at train time; the refund-policy update makes the same question diverge — stale vs. fresh.

Test
New facts → RAG; new behaviour → fine-tune. The lab also shows the reverse: ask for JSON output and only the tuned model honours it.

public/freshness.mjs

Pair 02

Loop vs. goal

Wrong model: "the agent is running" — motion mistaken for progress.

Failure: without a goal predicate the same loop runs to the 25-iteration budget cap, collecting 22 wasted citations at $0.02 each.

Test
What does "done" look like as a check the loop itself can evaluate? progress ≥ 3 is a goal; "keep researching" isn't.

public/loop.mjs

Pair 03

Prompt vs. harness

Wrong model: "the prompt works" — one good completion mistaken for a reliable pipeline.

Failure: a 60%-flaky model (wrapped prose or truncated JSON) sinks a bare JSON.parse caller to ~40% success; the harness's repair+retry+validate lands near 100%.

Test
Run it 100 times and count failures — then ask who retries.

public/harness.mjs

Pair 04

Context vs. memory

Wrong model: "it remembers" — reading this call mistaken for writing it down.

Failure: a turn-1 preference scrolls out of a 4-turn window by turn 9. The opposite mistake — stuffing full history into every call — recalls it but bills the whole conversation each turn.

Test
Will it know this next session, or did it scroll out of the window? Worth-keeping facts get written to a store.

public/memory.mjs

Pair 05

Prototype vs. production

Wrong model: "it works" — a learning artifact mistaken for a delivery vehicle.

Failure: the same artifact ships the prototype stage and is blocked on the production stage by four missing delivery gates.

Test
Which gates does it pass — learning gates (runs once, answers the question) or delivery gates (evals, rollback, monitoring, access control)?

public/gates.mjs

Bonus

The decision rule

classifyNeed() scores a plain-English need for fact-words vs. behaviour-words and recommends the tool. It scores the six team picks in examples/needs.json — three of them picked wrong.

Test
Deliberately naive keyword scoring — enough for a demo table, not a procurement tool.

Architecture

How the demo is built

LayerBehaviorEvidence
SimulatorsFive pure ES modules (freshness, loop, harness, memory, gates) shared by the browser UI, the CLI report, and the tests.public/*.mjs

Run locally

Inspect the evidence

npm test        # simulators + classifier + server
npm run scan    # side-by-side report across all five labs
npm run check   # both
npm start       # serve the lab on :3000

Nothing in the demo calls a real model — every "answer" is a deterministic fixture. That's what makes the divergence testable.

Limits

What this demo does not claim

  • Models are deterministic fakes: the flaky model is seeded RNG, the fine-tuned model is a frozen snapshot. Real systems fail in more colors — these five are the common ones.
  • Dollar figures ($24,000 training bill, $0.02/iteration, 120 tokens/turn) are illustrative constants, not benchmarks — the point is which side of the pair the cost lands on.
  • classifyNeed() is keyword scoring for the examples table — real RAG-vs-fine-tune decisions also weigh data volume, latency, privacy, and eval requirements.
  • The context window is modelled as a hard 4-turn cut; real context degrades gradually. Memory is modelled as perfect key-value recall; real memory retrieval can miss.
  • Four delivery gates is a teaching list — real production readiness is longer.
